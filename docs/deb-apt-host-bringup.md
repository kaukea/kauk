# Stand up `kauk.ai/debian` — the signmc apt repository (Releases-backed, non-growing)

## Design (operator-chosen, 2026-07-20)
A **real apt repository** — `apt install` **and** `apt update`/`apt upgrade`, **multiple
packages**, multiple versions — whose **`.deb` binaries live as GitHub Release assets**, so
**git never grows**. Only the small apt *text* metadata is versioned in this repo.

This replaces the earlier "binaries committed to `pool/` on GitHub Pages" assumption (that
grows the repo forever) and the "just `curl` a Release" idea (no update semantics — rejected).
Pure GitHub Pages cannot do this; the host is **fronted by Cloudflare**.

## How it works
apt downloads each package from `<base>/<Filename>`, where `Filename` comes from the
`Packages` index. Split the two:
- **Metadata** — `dists/<suite>/{InRelease,Release,Release.gpg, <comp>/binary-<arch>/Packages(.gz)}`
  — is small text, generated by **aptly/reprepro**, served from an origin (GitHub Pages out
  of `serialseb/kauk`, or R2).
- **Binaries** — the `.deb`s — are assets on a **single GitHub Release** in `serialseb/kauk`
  (tag e.g. `apt-pool`). Filenames are unique (`pkg_version_arch.deb`), so old and new
  versions coexist → apt can update, pin, and downgrade.
- **The bridge** — a **Cloudflare Worker / redirect rule** on `kauk.ai/debian/pool/*.deb`
  returns a **302 to the Release asset**
  (`https://github.com/serialseb/kauk/releases/download/apt-pool/<basename>`). apt follows
  redirects, so the bytes come from Releases. Everything else (`/debian/dists/*`) passes
  through to the metadata origin.

**Why the Worker is required:** GitHub Pages has no server-side redirect (only HTML
meta-refresh, which apt ignores), so a Pages-only host can't point `pool/` at Releases.
Cloudflare in front supplies the redirect.

## Steps
### 1. DNS — via Cloudflare (registrar action)
Put `kauk.ai` on **Cloudflare** (its nameservers / proxied records) so the Worker can run.
This replaces the bare "apex A-records to GitHub Pages" plan — that host cannot redirect.

### 2. Metadata origin — GitHub Pages on `serialseb/kauk`
- Enable Pages (source `main`); it serves the tiny `dists/` tree. Add `.nojekyll`.
- Cloudflare proxies `kauk.ai` → this origin; set Cloudflare SSL mode **Full**.

### 3. Cloudflare Worker (or single redirect rule)
- Route: `kauk.ai/debian/pool/*`.
- Action: `302 → https://github.com/serialseb/kauk/releases/download/apt-pool/<basename>`.
- Pass everything else to the Pages origin unchanged.

### 4. apt metadata — generated, signed
- aptly/reprepro emit `dists/` with `Filename: pool/<component>/<pkg>/<file>.deb` (the path
  the Worker redirects). Supports **multiple packages and multiple versions**.
- `Release` signed by the **SoftHSM-held OpenPGP key** (signmc Decision-038 — no operator
  hardware in any publish path). Publish `InRelease` / detached `Release.gpg`; serve the
  signing public key so installers pin it with `signed-by=`.
- **Only this text is committed** to `serialseb/kauk` — no binaries in git.

### 5. CI (signmc owns the push; Decision-038)
Per build: produce `.deb` → **upload it as an asset to the `apt-pool` Release** → regenerate
the metadata with the new version entry → commit only the metadata + re-sign `Release`.
`apt update` then sees the new version; `apt upgrade` installs it. Adding a second package
(e.g. the card-relearn udev package) is just another asset + another `Packages` entry.

## Result
- Real repo: multiple packages, `apt update`/`upgrade`, pin/downgrade. ✅
- Binaries in Releases → **git stays flat forever**. ✅
- Cost: a Cloudflare front (free tier). The host is no longer "just GitHub Pages".

## Amends signmc Decision-037
D-037 said the deb is "served by GitHub Pages out of `serialseb/kauk`". This design changes
that to **Cloudflare-fronted; metadata on Pages; binaries in a GitHub Release**. Record the
amendment on signmc's board so its `apt-metadata` / `ci` / `deploy` tasks target this shape.
kauk documents remain non-authoritative for signmc's package *contents* (Decision-038).

## Boundaries
- DNS / Cloudflare / Pages / Release uploads are **operator-gated**.
