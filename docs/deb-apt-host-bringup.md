## Candidate design: self-hosted, Releases-backed, non-growing
*(Only relevant if the operator chooses to self-host.)*

Goal that shaped it: a **real apt repo** (`apt install` + `apt update`/`upgrade`, multiple
packages/versions) whose **`.deb` binaries live as GitHub Release assets**, so **git never
grows** (a plain "commit binaries to `pool/`" repo grows forever; a bare `curl`-installer has
no update semantics — both ruled out in discussion).

### How it would work
apt downloads each package from `<base>/<Filename>` (`Filename` from the `Packages` index):
- **Metadata** — `dists/<suite>/{InRelease,Release,Release.gpg,<comp>/binary-<arch>/Packages(.gz)}`
  — small text, generated by **aptly/reprepro**, served from an origin (GitHub Pages out of
  `serialseb/kauk`, or R2).
- **Binaries** — assets on a **single GitHub Release** in `serialseb/kauk` (tag e.g.
  `apt-pool`); unique `pkg_version_arch.deb` names let versions coexist (update/pin/downgrade).
- **The bridge** — a **Cloudflare Worker / redirect rule** on `kauk.ai/debian/pool/*.deb`
  returns a **302 to the Release asset**; apt follows it. `/debian/dists/*` passes through to
  the metadata origin. *(GitHub Pages can't redirect — hence the Cloudflare front, and hence
  `kauk.ai` would need to route through Cloudflare.)*

### If self-hosted, the steps
1. **DNS via Cloudflare** (registrar) — so the redirect can run (not bare apex-A-to-Pages).
2. **Metadata origin** — Pages on `serialseb/kauk` (source `main`, `.nojekyll`); Cloudflare
   proxied, SSL **Full**.
3. **Cloudflare Worker/rule** — `kauk.ai/debian/pool/*` → `302` to
   `…/releases/download/apt-pool/<basename>`; pass the rest through.
4. **apt metadata** — aptly/reprepro emit `dists/` with `Filename: pool/…`. `Release` signed
   by the **SoftHSM OpenPGP key** (signmc Decision-038); serve the pubkey for `signed-by=`.
   Only this text is committed — no binaries in git.
5. **CI = the incoming processor** — a static host has no `dput` endpoint, so a GitHub Actions
   job runs aptly/reprepro: build `.deb` → upload the Release asset → regenerate + re-sign
   metadata → commit. `apt update`/`upgrade` follow.

### If this route is taken, it amends signmc Decision-037
D-037 said "served by GitHub Pages". This candidate is **Cloudflare-fronted, binaries in a
Release** — record on signmc's board *only if chosen*.
